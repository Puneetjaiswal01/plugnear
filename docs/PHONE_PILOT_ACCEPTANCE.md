# PlugNear phone and pilot acceptance checklist

Prepared 23 October 2026. Browser viewport checks are not physical-phone acceptance. Complete this with a consenting real driver and host at a genuine approved site before inviting the public to paid sessions. Do not create fake public listings or testimonials.

## What can be tested immediately on a real phone

Use current Safari on an iPhone and Chrome on Android. Start with a normal browser, not a social-media embedded browser.

| Step | Link/action | Pass evidence |
|---|---|---|
| Homepage | https://www.plugnear.in/ | Text and primary buttons readable, no sideways scrolling, menu opens/closes |
| Find | https://www.plugnear.in/find | App opens in find mode and shows email sign-in; no blank screen |
| Host | https://www.plugnear.in/host | App opens in host mode; after legitimate sign-in the host journey opens |

| Sign-in | Existing confirmed account, privately entered password | Account session persists appropriately; wrong password and sign-out handled |

## Provider-dependent email acceptance

The owner still needs verified custom SMTP. After setup, use independent test inboxes to test signup, confirmation, resend, expired/used links, reset and return to app. Check that links return to app.plugnear.in, never localhost. Do not disable confirmation or share passwords/OTP/reset links. Phone OTP and Google login require their own provider setup; an email form rendering is not proof of delivery.

## Physical charging session acceptance

1. Confirm genuine host identity, permission to host, equipment compatibility, electrical review and parking access. Verify the host's own VPA/payee details privately. A PlugNear review is not an electrical certification or insurance policy.
2. Confirm the real charger is approved, online and has a window spanning the intended session. Keep the first physical session attended by the host where practical.
3. On the driver's phone, allow location and confirm actual position; then deny it and verify map-area search remains usable. Check directions and distance interpretation.
4. Check connector and vehicle charging limit, parking/cable access, selected start/end in IST, duration, requested energy and displayed quote. No physical delivery guarantee follows from power × time.
5. Request once. Try an overlapping request from a second consenting driver: the server must prevent double booking. Record the expected host and driver statuses, without posting identities or addresses in public screenshots.
6. Host accepts. Confirm the recipient/amount in the UPI app before making a consented real transfer. Observe pending/failure handling; never retry a transfer just because the app hasn't updated.
7. Driver reports the reference. Host checks their own banking/UPI history before confirming receipt. A driver screenshot/reference does not count as bank verification.
8. Only then start the permitted session. Verify equipment operation together, finish in the app and release parking. Record actual delivered energy only if a suitable real meter is available; the pilot does not independently meter it.
9. Test cancellation and issue/dispute escalation without fabricating a failed transfer. Establish how a real host-issued refund is recorded and verified. No automatic refund/insurance guarantee is offered.
10. Call the participants after the session: capture access problems, request taps/time, charging result and support effort. Share only redacted evidence internally.

## Human acceptance record

Record date, phone/OS/browser version, scenario, pass/fail, redacted evidence, operator and next action. This repository has **no completed physical-device acceptance record**. Do not convert automated test passes into a completed human test or a full-launch claim.

## Recruitment and soft-launch sequence

Delhi NCR remains the recruitment geography. Select one practical society/RWA cluster and compatible driver/vehicle cohort with real permission, rather than claiming city-wide supply. A first supervised host/session is the immediate gate. The proposed targets of 20–30 reviewed hosts and 50–100 invited drivers are planning goals, not achieved numbers or guaranteed demand. Build a host recruitment brief and contact people only through an owner-authorized campaign. No outreach was sent by this work.

Before broad paid acquisition: complete delivery/admin/host gates, agree legal/insurance/privacy responsibilities with qualified advisers, run real sessions, fix the top observed friction points and publish only consented authentic photographs and results. Domain email, WhatsApp Business, stored waitlist, analytics collection, gateway onboarding, reviews and roaming remain separately provisioned work; do not fabricate accounts or service guarantees.
